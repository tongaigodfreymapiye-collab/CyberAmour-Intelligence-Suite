CYBERAMOUR INTELLIGENCE SUITE — PATCH DEPLOYMENT NOTES

THIS ZIP IS A SOURCE PATCH, NOT A FULL REPOSITORY EXPORT.
It does not contain package.json, the full src tree, .github/workflows/deploy.yml, Firebase configuration, or the complete backend. Do not upload every extracted item as a replacement for your repository, and do not delete existing files.

APPLY THE PATCH
1. Extract the ZIP.
2. Copy the included files/folders into your existing CyberAmour repository, preserving the directory structure and overwriting only the matching source files.
3. Keep your existing package files, .github workflows, logo assets, data/, Firebase configuration, .git, and local databases.
4. Rotate the exposed sensor token using scripts/rotate-sensor-token.ps1 and paste it into the local sensor token field in CyberAmour. Do not share or commit the token.
5. Start the sensor with scripts/setup-sensor.ps1 and keep its terminal open.
6. Run the existing repository's lint, build, release audit, and tests. The checks must be run from the full repository, not from this patch directory.
7. Inspect git diff and git status, then commit and push only intended source changes.

GITHUB PAGES
The actual deployment workflow is not included in this patch. In your existing GitHub repository, verify that a workflow builds the Vite app and deploys the generated dist/ directory, and that Settings > Pages > Build and deployment > Source is set to GitHub Actions. Do not publish /src or a raw development entrypoint.

SECURITY
- A static frontend cannot keep private API keys secret. Revoke/rotate any valid exposed keys and keep server secrets out of frontend code.
- The local sensor binds to 127.0.0.1 and requires bearer-token authentication for protected actions.
- A successful build is not proof of end-to-end endpoint protection. Verify sensor authentication and test a Microsoft Defender scan on the target Windows computer.
